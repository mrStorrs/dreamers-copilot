# Rules Pruned V1

Date created: 2026-07-03

Input reviewed: `inital-rule-research.md`, candidate rule rows 1-1124.

Goal: collapse the researched candidate rules into a smaller set of unique, broadly applicable code commandments. Rules that were domain-specific, technology-specific, or too similar to another rule were merged into a higher-level rule. Row references point back to the source rows in `inital-rule-research.md` and are maintained as an exhaustive audit map for the 1,124 reviewed rows.

## Pruning Standard

- Keep a rule only when it applies across many kinds of code or expresses a general principle behind a specialized source.
- Collapse rules that differ mainly by technology, layer, or example.
- Prefer clear imperatives over slogans.
- Keep traceability back to the research table.
- Treat this as version 1: useful, compact, and reviewable, not the final commandment wording.

## Current Judgment

This is intentionally still larger than a final "ten commandments" list. The research set spans secure coding, correctness, testing, APIs, data, operations, accessibility, supply chain, distributed systems, UI, AI, and regulated systems. Collapsing below this version would require choosing a target audience and deciding which important domains should become sub-rules rather than peer commandments.
